Web Crawler Agent with Risk Engine

System Architecture and Process Flow Documentation

System Overview

The Web Crawler Agent with Risk Engine integration is a sophisticated system that combines web crawling capabilities with financial risk assessment. The system allows users to interact with a conversational agent that can extract financial information from company websites and analyze the company's risk profile.

Figure 1: High-level System Architecture

Key Components

  • Streamlit UI: The user interface built with Streamlit that allows users to interact with the agent
  • Agent: The core component that processes user messages and orchestrates web crawling and risk analysis
  • Web Crawler: Dual-crawler system with Simple Crawler (requests/BeautifulSoup) as primary and Playwright as fallback
  • Risk Engine: FastAPI-based service that evaluates company risk based on financial metrics

Process Flow

The system follows a specific flow to process user requests, crawl websites, and analyze risk.

Figure 2: Process Flow Diagram

Process Steps

  1. User Input Processing: The agent analyzes the user's message to determine if it's a web crawling request, risk analysis request, or general query
  2. Command Detection: The agent uses pattern matching to identify website URLs or commands (e.g., "scrape Tesla website")
  3. Web Crawling: If the request requires web crawling, the agent:
    • Tries the Simple Crawler first (requests/BeautifulSoup)
    • Falls back to Playwright crawler if needed
    • Uses progressive retries with increasing timeouts
  4. Risk Analysis: If the request is for company risk analysis, the agent:
    • Crawls the company website
    • Extracts financial metrics using pattern matching
    • Sends the data to the Risk Engine API
    • Processes and formats the risk assessment results
  5. Response Generation: The agent formulates a response based on the crawled content or risk analysis results

Financial Metrics Extraction

The system uses pattern matching to extract financial metrics from company websites.

Figure 4: Financial Metrics Extraction Process

Extraction Techniques

  • Debt-to-Equity Ratio: Regex patterns to find mentions of debt-to-equity followed by numeric values
  • Net Profit: Patterns to extract profit/earnings figures, handling different formats ($2.3 million, $2,300,000)
  • Sector Detection: Keyword frequency analysis to determine the most likely business sector
  • Negative News Score: Counting occurrences of negative terms relative to total content length
  • Late Payments Rate: Usually defaulted to a moderate value (0.1) as it's difficult to extract reliably
Note: When specific metrics can't be found, the system uses default values:
  • Debt-to-Equity Ratio: 2.0 (moderate risk)
  • Net Profit: 0 (break-even)
  • Negative News Score: 0.3 (moderate)
  • Late Payments Rate: 0.1 (moderate)
  • Sector: "general" (standard risk multiplier)

Implementation Details

Web Crawler Components

  • Simple Crawler: Uses requests and BeautifulSoup, provides better reliability and faster performance
  • Playwright Crawler: Used as a fallback for complex websites, handles JavaScript-heavy pages
  • Retry Logic: Progressive retries with increasing timeouts (15s, 22.5s, 30s)
  • Concurrency Management: Limited to 3 workers to prevent resource exhaustion

Risk Engine API

  • FastAPI Framework: High-performance API with automatic documentation
  • SQLAlchemy ORM: Database interactions for storing risk evaluations
  • Risk Calculator: Core logic for calculating risk scores based on financial metrics
  • Recommendation Engine: Generates tailored recommendations based on risk profile and business sector

Agent Message Processing

  • Command Detection: Identifies web crawling commands (e.g., "scrape Tesla website")
  • URL Construction: Automatically constructs URLs for known companies (e.g., "Apple" → "https://www.apple.com")
  • Risk Query Detection: Identifies risk analysis requests (e.g., "analyze risk for Company X")
  • Response Formatting: Formats risk assessments with scores, factors, and recommendations

Example Workflow

Let's walk through a complete example of a risk analysis request:

1. User sends message:

"Analyze the risk for Tesla https://www.tesla.com/investor"

2. Agent detects risk analysis request

  • Identifies "analyze risk" as a risk analysis request
  • Extracts "Tesla" as the company name
  • Identifies "https://www.tesla.com/investor" as the URL to crawl

3. Web crawler extracts content

  • Simple Crawler retrieves the content from Tesla's investor relations page
  • Content is processed to remove HTML tags and extract plain text

4. Financial metrics extraction

  • The system uses pattern matching to extract financial data
  • For example, it might find:
    • Debt-to-Equity Ratio: 1.2
    • Net Profit: $5.5 billion
    • Sector: Detected as "technology" (with automobile keywords)
    • Negative News Score: 0.15 (calculated from content analysis)
    • Late Payments Rate: 0.1 (default value)

5. Risk Engine calculation

  • Data is sent to the Risk Engine API
  • API calculates a weighted score based on the factors
  • Basic calculation: (0.3 * 0.5 + 0.25 * 0.1 + 0.2 * 0.2 + 0.25 * 0.4) * 1.0 * 100 = 30.0
  • Risk level determined as "Low Risk" (score < 40)
  • Recommendations generated based on the low risk profile

6. Response presentation

Risk Level: Low Risk

Risk Factors:

- Strong positive net profit indicates excellent financial health
- Low negative news coverage

Recommendations:

- Annual risk reassessment recommended
